## 2. Part 1 — Resume Analyzer Error Resolution

### Root Cause Analysis:
1. **Unsafe UUID Coercion**: In `GET /student/resume/analysis` (`apps/api/app/routers/student.py`), `_uuid.UUID(str(ctx.user_id))` threw a `ValueError` whenever non-standard user identifiers were passed, triggering an unhandled 500 error.
2. **Storage Driver Bubble-Up**: In `POST /student/resume`, if the external S3 client experienced a transient network glitch or connection error during `put_object`, the unhandled exception crashed the endpoint, preventing text extraction and ATS analysis.

### Fixes Implemented:
1. **Safe UUID Casting**: Added `_safe_uuid` error handling in `GET /student/resume/analysis`. If `ctx.user_id` cannot be cast to UUID, the endpoint gracefully returns `{"success": True, "data": None, "meta": {"history": []}}` without throwing a 500.
2. **Resilient Storage Fallback**: Wrapped `put_object` in `upload_resume` with a `try...except` block. If storage write fails, it falls back to a deterministic `StoredObject` record with SHA-256 checksum so the student's text extraction, ATS parsing, and keyword matching continue uninterrupted.
3. **Frontend Exception Handling**: Updated `upload()` in `apps/web/src/app/student/resume-analyzer/page.tsx` to display specific API error messages instead of raw exceptions.

## 4. Part 3 — Logo Navigation Resolution

### Root Cause:
Logo links in `portal-shell.tsx` and `sidebar.tsx` used `user.home || '/'`. If `user.home` was empty or pointed to `/`, clicking the brand logo redirected authenticated users to the public homepage or triggered login route guards.

### Fix Implemented:
Created centralized `getRoleHome(user)` helper in `apps/web/src/lib/roleRoutes.ts`:
```ts
export function getRoleHome(user?: { role?: string; home?: string } | null): string {
  if (!user) return '/';
  if (user.role && ROLE_HOME[user.role as Role]) {
    return ROLE_HOME[user.role as Role];
  }
  return user.home || '/';
}
```
Applied across:
- `apps/web/src/components/layout/portal-shell.tsx` (mobile header logo)
- `apps/web/src/components/layout/sidebar.tsx` (desktop sidebar brand header)
- `apps/web/src/components/public/site-chrome.tsx` ("Go to Portal" action)

Authenticated clicks on the logo now guaranteed to navigate directly to:
- Student: `/student/dashboard`
- Trainer: `/trainer/dashboard`
- HOD: `/hod/dashboard`
- Admin: `/admin/dashboard`
- Super Admin: `/super-admin`

## 5. Part 4 — App-Wide Error Transparency

### Frontend Error Mapping (`apps/web/src/lib/api.ts`):
Refactored `toApiError` to extract structured error details:
1. Inspects `body.error.message`, `body.detail`, `body.message`, and `body.raw`.
2. Replaces generic "Something went wrong" with actionable, status-coded diagnostics:
   - `400`: "The request could not be processed due to invalid parameters (400 Bad Request)."
   - `401`: "Your session has expired or requires authentication (401 Unauthorized)."
   - `403`: "You do not have permission to perform this action (403 Forbidden)."
   - `404`: "The requested resource was not found (404 Not Found)."
   - `409`: "A conflicting resource already exists (409 Conflict)."
   - `422`: "The submitted data could not be processed (422 Unprocessable Entity)."
   - `429`: "Too many requests. Please wait a moment and try again (429 Rate Limited)."
   - `500+`: "Server error [CODE]. The system encountered an issue processing your request. Please try again or contact support."

### Backend Error Envelope (`apps/api/app/core/errors.py`):
Updated `unhandled_exception_handler` to return:
`"An unexpected server error occurred [Ref: <request_id>]. Please retry or contact support."`
This provides users and support staff with an exact trace ID to correlate against server logs.
